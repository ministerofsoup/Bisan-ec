# プラットフォーム比較検討（ドラフト）

> 目的：ECの基盤を **A. Shopify（Shopify CLI 利用）** とするか、**B. Stripe を活用したスクラッチ構築** とするかを比較し、意思決定する。
> 現フェーズでは「どちらを選ぶか」を判断するための材料を整理する。

## 0. 前提

- 最初は **単一商品（クナーファ・冷凍）** の販売。SKUは少数。
- 食品EC特有の要件：冷凍便、特定商取引法（特商法）表記、食品表示、賞味期限、ギフト対応。
- 運用は小規模チーム想定。**運用負荷の低さ**が重要。
- 将来的に商品ラインナップを拡張する可能性あり。

## A. Shopify（Shopify CLI）

Shopify 上にストアを構築。テーマ開発は **Shopify CLI** + Liquid（または Hydrogen/React によるヘッドレス）で行う。

### メリット
- 決済・カート・在庫・注文管理・配送・税が**最初から揃っている**。自前実装がほぼ不要。
- 特商法/領収書/メール通知などEC運用機能が標準。**運用負荷が低い**。
- 冷凍便の送料設定、地域別送料、ギフトなども設定で対応しやすい。
- Shopify CLI でテーマをローカル開発・バージョン管理でき、トンマナを反映したカスタムテーマが作れる。
- 拡張（アプリ・SKU追加）が容易。スケールしても破綻しにくい。

### デメリット
- 月額費用＋決済手数料（Shopify Payments 以外はさらに手数料）。
- デザイン・挙動は Shopify の枠組みに一定従う必要がある（ヘッドレス化で自由度は上げられるが工数増）。
- 細かい独自要件は Liquid/アプリの制約を受けることがある。

### 向いているケース
- **早く・安全に・運用負荷低く**立ち上げたい。EC機能を作り込みたくない。

## B. Stripe を活用したスクラッチ構築

フロントを自前で構築し、決済に **Stripe（Checkout / Payment Links / Payment Intents）** を用いる。

### メリット
- デザイン・体験の**自由度が最大**。トンマナを100%反映できる。
- 小さく始めるなら **Stripe Payment Links / Checkout** で決済だけ任せ、商品ページは静的に近い構成も可能。
- 月額固定費を抑えやすい（Stripeは基本従量）。
- インフラを自由に選べる（例：本環境で利用可能な **Cloudflare（Workers / Pages / D1 / R2）** に載せる構成も検討可能）。

### デメリット
- カート・在庫・注文管理・特商法・領収書・配送計算・メール通知などを**自前で実装/連携**する必要。
- 食品EC特有の要件（冷凍便送料、ギフト、賞味期限管理）も自前。**初期工数と運用負荷が高い**。
- セキュリティ・法令対応（特商法、個人情報）も自己責任の範囲が広がる。

### 向いているケース
- ブランド体験を最優先し、独自UXに投資できる。開発・保守リソースがある。

## 比較サマリ

| 観点 | A. Shopify | B. Stripeスクラッチ |
| --- | --- | --- |
| 立ち上げ速度 | ◎ 速い | △ 時間がかかる |
| 初期工数 | ◎ 小 | ✕ 大 |
| 運用負荷 | ◎ 低 | △〜✕ 高 |
| デザイン自由度 | ○（ヘッドレスで◎） | ◎ |

| 拡張性（SKU増加） | ◎ | ○（作り込み次第） |

## 推奨（たたき台）

> **最初のクナーファ単品販売は Shopify での立ち上げを推奨**。
>
> 理由：単品〜少数SKU・小規模運用・食品EC要件（特商法/冷凍便/注文管理）を考えると、
> EC機能が標準で揃う Shopify が **立ち上げ速度・運用負荷・安全性** で優位。
> トンマナは Shopify CLI のカスタムテーマ（必要ならヘッドレス Hydrogen）で十分表現できる。
>
> 一方、**ブランド体験への投資を最優先**し開発リソースを割けるなら、
> Stripe + 独自フロント（＋Cloudflare 等）でのスクラッチも選択肢。
> その場合は段階的に（まず Stripe Checkout で決済だけ任せる等）始めるとリスクを抑えられる。
